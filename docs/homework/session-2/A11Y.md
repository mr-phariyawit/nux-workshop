# SiteOps — A11Y.md

> **Simulated.** The course's A11Y.md slide was not reachable, so this contract is
> authored from WCAG 2.2 AA and the SiteOps context (`UX.md` WORLD-001). It is
> written the way the course frames every contract: rules an agent must satisfy,
> each with a verification method, so an agent can fix code against it and a test
> can prove it.

## 0. How an agent uses this file

1. Read `DESIGN.md` (visual tokens) and `UX.md` (behaviour) first; this file constrains both.
2. Every rule below has an ID `A11Y-###`, a strength, and a **Verify** line. Automated rules are checked by axe-core in `tests/session-2/`. Manual rules go in the PR checklist.
3. When fixing code, cite the rule ID in the commit or PR description.
4. Do not "fix" accessibility by hiding content from assistive technology. Do not add `tabindex` greater than 0. Do not remove focus outlines.

Baseline: **WCAG 2.2 Level AA**, plus stricter targets where the field context demands it.

## 1. Perceivable

### A11Y-001 — Text contrast
- Strength: `must`
- Rule: body and label text ≥ 4.5:1 against its background; large text (≥ 24 px regular or ≥ 19 px bold) ≥ 3:1. Applies in both themes.
- Why here: dim plant rooms and outdoor-brightness screens.
- Verify: axe `color-contrast`; token table in `DESIGN.md` §2.2.

### A11Y-002 — Non-text contrast
- Strength: `must`
- Rule: UI component boundaries, focus indicators, and status icons ≥ 3:1 against adjacent colours.
- Verify: axe (partial), manual token audit.

### A11Y-003 — Not colour alone
- Strength: `must`
- Rule: priority, status, sync state, and validation errors are conveyed by icon **and** text in addition to colour.
- Why here: colour-vision deficiency plus low-light viewing; `UX.md` RULE-006.
- Verify: axe `color-contrast` does not cover this; design review + snapshot review of `StatusBadge`.

### A11Y-004 — Text alternatives
- Strength: `must`
- Rule: every informative image and every icon-only control has a text alternative. Decorative icons are `aria-hidden="true"`. Evidence photos get `alt` = "หลักฐาน ใบงาน #ID ถ่ายเมื่อ {time}".
- Verify: axe `image-alt`, `button-name`, `link-name`.

### A11Y-005 — Language
- Strength: `must`
- Rule: `<html lang="th">`; English or Burmese passages marked with `lang`.
- Verify: axe `html-has-lang`, `html-lang-valid`.

### A11Y-006 — Reflow and zoom
- Strength: `must`
- Rule: no horizontal scroll at 320 px width; content usable at 200% zoom.
- Verify: manual at 320 px and 200%.

## 2. Operable

### A11Y-007 — Target size (stricter than WCAG)
- Strength: `must`
- Rule: field surface targets ≥ 56 × 56 CSS px with ≥ 8 px spacing; dashboard ≥ 44 × 44. WCAG 2.5.8 minimum (24 px) is never used as a justification.
- Why here: gloves, one-handed use (`UX.md` INS-002).
- Verify: Playwright bounding-box check in `tests/session-2/`.

### A11Y-008 — Keyboard
- Strength: `must`
- Rule: all functionality operable by keyboard on the dashboard; no keyboard traps; logical tab order following visual order; no `tabindex` > 0.
- Verify: axe `tabindex`; manual tab-through.

### A11Y-009 — Focus visible
- Strength: `must`
- Rule: `:focus-visible` shows a 3 px `--color-focus-ring` outline with 2 px offset; never `outline: none` without replacement.
- Verify: axe (partial); manual.

### A11Y-010 — Motion
- Strength: `must`
- Rule: respect `prefers-reduced-motion`; nothing flashes more than 3 times per second; SLA countdown updates without animation.
- Verify: manual; CSS review.

### A11Y-011 — Timing
- Strength: `should`
- Rule: undo toasts stay ≥ 5 s and pause on hover/focus; no session timeouts on the field surface while offline.
- Verify: manual.

## 3. Understandable

### A11Y-012 — Labels and instructions
- Strength: `must`
- Rule: every form control has a visible `<label>` associated by `for`/`id` (placeholder is not a label); required fields say so in text.
- Verify: axe `label`.

### A11Y-013 — Error identification and suggestion
- Strength: `must`
- Rule: errors are announced (`aria-describedby` to the message, `aria-invalid="true"`), located next to the field, and say how to fix it.
- Verify: axe `aria-valid-attr-value`; manual.

### A11Y-014 — Consistent identification
- Strength: `must`
- Rule: the same action uses the same icon and label everywhere (`DESIGN.md` §7).
- Verify: design review.

### A11Y-015 — Plain language
- Strength: `should`
- Rule: field copy ≤ 3 words per button; no jargon; glossary terms from `UX.md` §6 only.
- Verify: copy review.

## 4. Robust

### A11Y-016 — Semantics
- Strength: `must`
- Rule: native elements first (`<button>`, `<a>`, `<input>`); ARIA only to fill gaps; landmarks (`main`, `nav`, `header`) present; one `h1` per screen.
- Verify: axe `button-name`, `landmark-one-main`, `page-has-heading-one`, `region`.

### A11Y-017 — Live regions
- Strength: `must`
- Rule: offline banner is `role="status"`; sync failures are `role="alert"`; SLA countdown is `role="timer"` with `aria-live="off"` and a text summary updated each minute, not each second.
- Verify: manual with screen reader.

### A11Y-018 — Autocomplete and input purpose
- Strength: `should`
- Rule: login and profile fields carry `autocomplete` tokens (`username`, `current-password`).
- Verify: axe `autocomplete-valid`.

## 5. Automated gate

The test in `tests/session-2/login-a11y.test.ts` runs axe with tags
`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa` and additionally checks
A11Y-007 target sizes. A page fails the gate on any violation. The gate is a floor,
not the standard; the manual rules above still apply.
